# 3. Building a $0 Microsoft 365 help desk for a nonprofit

**Environment:** Small Dallas community nonprofit on Microsoft 365, volunteer-heavy staff, no IT budget

## Situation
Staff asked for IT help through texts, personal email, and hallway conversations. Requests got lost, there was no history, and the same questions came up repeatedly. Internal staff tools were also too easy to reach from the public website.

## Requirements
- Use only tools the organization **already licenses** (Microsoft 365)
- Easy enough for non-technical staff
- Every request tracked from submission to close
- Internal tools and information **never** visible on public pages

## Action
- **Ticket intake through three channels** that all land in one place:
  - a **Power App** form for staff
  - a shared **help@** mailbox
  - a **Teams** channel
- A small team (me + staff helpers) works the queue; AI-assisted triage suggests responses and draft replies, but **a human always makes the final call**.
- **Access control:** moved staff-only tools behind Microsoft 365 sign-in and a credential-protected staff page; reviewed the public site so no internal links or operational details were exposed.
- **Phones at $0:** Microsoft Bookings for appointment scheduling plus a free Google Voice number, with a documented upgrade path to Teams Phone when budget allows.
- **Documentation:** one concise master manual plus role-specific instructions for each team member, written for a non-technical reader, with every needed link and no dead or empty documents.

## Result
- A single, trackable queue instead of scattered requests
- No new software spend
- Staff can self-serve common answers from the manual
- Internal resources separated from the public website

## Skills shown
Microsoft 365 administration · Power Apps · Exchange shared mailboxes · Teams · access control · user documentation · cost-constrained solution design
